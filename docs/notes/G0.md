## 1. What Was Documented

Task G0 establishes the complete visual redesign specification and reference architecture for Pawmodoro v3. Rather than writing ad-hoc assembly code or making arbitrary guesses about layouts and data formats, this addendum creates an authoritative, repository-grounded engineering foundation that subsequent implementation agents (G1 through G15) can follow without ambiguity.

Key documented subsystems include:
1. **Responsive Layout Tiers (Compact, Standard, Grand):** Precise entry conditions and element behavior for 80×24, 100×30, and 120×36 terminal resolutions. Frame width cap raised from 100 to 120 columns with centering kept.
2. **Half-Block Sprite Model:** 1 cell = 2 stacked pixels using `▀` and `▄`, transparent pixel filling via surface slots, deterministic binary format with RLE encoding, even pixel heights, and mandatory 7-bit ASCII fallbacks.
3. **Extended 24-Slot Theme Model & Cat Coats:** Preserving v2 slots 0–11 verbatim; introducing slots 12–23 (`SLOT_BG`, `SLOT_SURFACE`, `SLOT_SURFACE_ALT`, `SLOT_BORDER_FOCUS`, `SLOT_TITLE_ALT`, `SLOT_TEXT_INV`, and 6 art slots); establishing six persistent Cat Coat presets (Orange Tabby, Gray Tabby, Black, White, Cream, Tuxedo).
4. **Persistent `settings.dat` Version 2:** Exact 48-byte binary layout with magic `PAWS`, full validation, deterministic fallback to defaults, and backward-compatible migration from legacy 24-byte Version 1 settings files.
5. **Buffer Safety & Color State Optimization:** Expanding `out_buf` to 16,384 bytes in `.bss`, establishing a mathematical overflow invariant and error flag (`gfx_overflow`), requiring single `sys_write` flushes, and introducing local color-escape skipping to minimize terminal overhead.
6. **xterm SGR Mouse Support:** Specifying click-only mouse event tracking (`KEY_MOUSE = 0x10A`), coordinate conversion, hit-test dispatching, a persistent Settings toggle, and guaranteed terminal cleanup on all exit paths.
7. **Target Dashboard Mockup Specification:** Mapping every visual element in `docs/reference/reference_home_page.jpg` (cat logo, gradient title, greeting, sleeping cat, sidebar buttons, demo toggle, mascot stat card, habits bar with cat-head marker, daily tip, and quick journal) to widgets and real data sources.
8. **Smoke Suite Repairs (Task G14):** Diagnosing the five flawed smoke checks in `tests/smoke.sh` (scenarios 21, 27, 29, 30, and 31) and the `grep -P` ASCII checks.
9. **Asset Preparation Guide (`docs/reference/README.md`):** Comprehensive inventory of all 20 required sprites with tier-specific dimensions, animation frame counts, ASCII fallbacks, and the planned converter specification (`tools/png2sprite.py`).

## 2. Why These Decisions Matter

- **No Breakage of Working Assembly Code:** Pawmodoro already has fully functional Pomodoro timer logic, habit tracking arithmetic, and journal file storage. By strictly defining the visual interface as an addendum to PRD v1 and v2, the redesign transforms the aesthetics without risking regressions in core business logic.
- **Buffer Safety in Pure Assembly:** Drawing full-color pixel art in terminal emulators consumes substantial escape sequence bandwidth (~25 bytes per cell). Doubling `out_buf` to 16 KiB and implementing local color skipping ensures that rich frames never silently truncate or corrupt the terminal.
- **True GUI Feel on the Command Line:** Combining half-block pixel art, dark surface fills, responsive layout tiers, and mouse click reporting makes Pawmodoro feel like a modern graphical desktop application while remaining 100% lightweight 32-bit Linux assembly.
- **Deterministic and Testable:** Every single functional requirement (`FR-G1` through `FR-G22`) is bound to concrete acceptance criteria and verification commands, eliminating subjective guesswork for coding agents.

## 4. Main Design Choices

1. **Theme Indirection for All Art:** Rather than hardcoding colors into sprites, every pixel maps to a theme slot. This allows user customization and seamless Cat Coat switching.
2. **Deterministic Tiers Over Free Resizing:** Terminal fonts and window sizes vary wildly. By locking layout decisions into Compact (80×24), Standard (100×30), and Grand (120×36), the interface maintains visual balance and avoids overlapping widgets.
3. **Local SGR State Caching:** Limiting ANSI escape skipping to local graphics blocks avoids desynchronization bugs caused by legacy routines that emit raw `ansi_reset`.
4. **Backward-Compatible Settings Upgrade:** Version 2 files are 48 bytes, but the loader continues to accept 24-byte Version 1 files, populating newly added fields with safe defaults and upgrading on the next save.
